# 2026-10-23

## 大型迷宫寻宝博弈游戏（maze-quest）· 规划轮 P0–P2

用户发起：128×128 迷宫寻宝游戏，HY4 preview 大模型驱动 3 个 AI agent 做博弈决策，1 个玩家角色（可手工/自制 JS 脚本/提示词 AI 托管）。45° 仿 3D 俯视角、art deco 低饱和马卡龙风格。

### 用户已拍板的四项（不可推翻）
1. 交付形态：**网页版 + 本地 Node 代理**，API Key 只存代理进程，绝不进前端
2. 节奏：**回合制同步步进**，一回合走一格
3. 体力：从 1000 **大幅下调到 300~500 量级**（最终 400）
4. 玩家托管：**脚本沙箱 + 提示词托管双通道**都要

### 用户已确认的玩法
「迷雾不要」→ 否掉战争迷雾。最终视野模型：**地形全公开 + 宝石/宝箱位置全球公开，仅对手位置受视野半径限制**。

### 关键设计裁定（创意总监 v1.1，含对原规则的改动）
- **出口 = 迷宫中央区域环上四座「归航传送门」**（半径 ~45 格，约 (32,32)/(95,32)/(32,95)/(95,95)），非四条边中点。原因：实测对角出口要 248~320 步，400 体力几乎必败。**代价是"出口不在边缘"与直觉冲突，需用户知情**
- 体力 400（200 局仿真：93% 局面捡到 ≥3 个宝物，仅 16% 被单人通吃）
- 五色宝石各 1 分，**重生封顶 2 次**（共 3 代 15 分）防无限刷分
- 宝箱：全局 1 个，**重生 2 次、间隔 ≥60 回合**；奖励 50%→1~5 分 / 50%→**25~50 体力**（用户原值 5~10）
- 平局加一层：**达成回合早者胜**
- 主动停留扣 1 体力；被挡扣 0；四面全阻扣 0（杜绝堵杀，卡位不掉体力）
- 同格抢占：**双方都不动**（采纳架构方案，天然确定性）
- maxTurns 600；墙密度 0.355；结束条件 = 全员结算
- **需求 #20 常驻出口罗盘是 P0**（出口藏在迷宫里，没罗盘无法玩）

### 关键技术裁定（架构总监）
- 渲染：**Canvas 2D 原生、零第三方依赖**（分块 8×8 预烘焙，每帧 ~40 blit，1080p 可见 2025 格）
- 迷宫生成：growing-tree + braid + 削墙 keep=0.72（**警告：stride-1 逐格生长在 128×128 会退化成空地，密度仅 0.031**）
- LLM 节流：**方案 B 每 8 回合重规划 + 事件触发，本地 BFS 执行**——每局约 120 次调用 / 0.16M token，比每回合全调用省 ~85%
- 四层降级链 L0–L3，对局绝不中断
- 确定性：stateHash（canonical JSON + FNV-1a），`Math.random` 只在 rng.js、`Date.now` 只在 clock.js，具名 RNG 流
- **沙箱诚实边界**：防误触 + 可观测 + 可复盘，不是密码学隔离。真防作弊需权威服务器，与零后端纪律冲突，明确不做

### 规则终稿 v1.3（创意总监）
- **出口最终 = 四条边中点 + 就近分配（顺时针）**，spawn→exit 约 90 步，硬校验区间 [85,100]，落在区间外退回内侧环。创意自己推翻了内侧环，理由：出口与宝石两个目标同向会让核心取舍失去空间张力；就近后出口在外围、宝石在中心，方向相反，玩家路线呈"深入→折返"V 形
- **死锁漏洞补丁（v1.3 新增）**：死胡同互堵时"四面全阻扣 0 + 被挡扣 0" → 双方都不掉体力 → 永久僵持。补丁：四面全阻改扣 1；连续 ≥3 回合未位移者第 4 回合起每回合扣 1 → 任何僵持 ≤403 回合内由体力耗尽终结
- 卡位战术定位：**不主推、不禁止、不做特殊处理**，代价结构刻意做成对发起方亏本
- 视野三层：玩家屏幕全图 / LLM 地形 patch 15×15 / 实体可见半径 R=9（19×19）。**15×15 patch 只裁地形，与实体记忆无关**
- 重规划事件最终 6+1 条；终盘阈值动态 `剩余体力 ≤ d(→exit) × 1.3`（否决架构的 ×1.15+8：绝对常数在 d=10 时余量 95% 等于没告警）
- 脚本降级两套并存定优先级：L2 先判（连续 10 回合异常→切手动），L1 后判（累计 5 次非法意图→本局每回合停留）
- 离散度口径统一为"极差/均值 ≤ 0.30"（创意原"极差/中位数"是自造口径，作废）
- 单局 **320–400 回合**（创意修正了自己把路径长度当回合数的错误）→ 加速控制是 P0 里的 P0

### 撒点改革是必修项，不是优化项
旧撒点下单人独占可捡 **15.05 件、五色全拿 100%** → **游戏被打穿**（"抢"这件事根本不存在）。改后：可捡 2.97、≥3 件 61%、包围盒 18→123.7 格。
分布健康性已验证：可捡数按距出生点分桶，近桶（<40 步）仅 **15.4%**、中远桶 84.6%、全部拾取均值 74.7 步 → **不是门口堆货，不需重铺**。

### 宝石 10 颗（**仍待用户拍板**）
边中点口径：零收获率 **13.0% → 5.7%**，人均 **1.75 → 2.47**。
⚠ 交付说明里一度误写成"21% → 10%/1.54 → 2.40"——那是**内侧环**口径，比真实值严重一倍，已改。

### 美术两处（锚点是主理人/架构的表述错误，已纠）
- **锚点不能"统一"**：tile 锚点 (32,32)=菱形中心，角色/宝石/宝箱锚点 **(32,56)**=脚下落点。画布仍 64×64 不需放宽，角色高度恢复 **56px**（一度被误压到 32px）
- **墙压暗**：为过"地/墙明度差 ≥40"，墙从中性米色改成中调暖灰（V=185），ΔV 20→48。这**偏离用户"低饱和马卡龙"字面直觉**（马卡龙第一联想是彩色不是暖灰）→ 裁定做 **A/B 两套色值**，灰盒闸门让用户自选，不替他决定

### 三条新教训（本轮真实发生，已写入交付说明）
1. **过期判据会把正常决策包装成例外**。曾写"严格按硬校验边中点不通过"，但那条校验当时已作废——**例外需要有人点头，规矩不需要**
2. **观测 ≠ 规范，猜测 ≠ 门槛**（上一条的反向版本）。"失败率不得 >35%"其实是旧配置的**观测值**被当规范挂了下来；"spawn→exit ≈90/绕路 1.39"则是**两个猜测值碰巧抵消**出一个看起来对的结果——**这类错误不报错**
3. **扩散出去的错数比源头那个错数更难收回**。改数值的人与用数值的人隔了三层，收回时要挨个通知且不知道是否通知全 → 宁可少写一个数，不写一个错的数

### 口径纪律（本轮踩过多次，已写进交付说明）
同一件事在不同脚本/配置下会给出差 1.9 倍的数。引用任何数字必须带三元组 **(出口方案, 宝石数, 竞争度)**：
- 宝石数：t2 跑 5 颗（人均 2.97）、bench-match 跑 10 颗（人均宝石 2.52）→ **5 颗口径的数不得用于 10 颗结论**
- 竞争度：单人独占可捡 3.59 vs 四人竞争 2.97，**差 30 个百分点**
- 出口方案：内侧环与边中点各一套数（零收获 21% vs 13%），采用边中点则只用边中点口径
