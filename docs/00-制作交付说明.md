**关于第 2 项，创意总监的原话（我原样转给你，含代价那半句）：**

> 「实测每色 1 颗时，**每 9 个角色里就有 1 个跑完全场一颗宝石都拿不到**——那不是激烈的抢夺，是坐牢。改成每色 2 颗后，这个比例从 **11.3% 降到 4.3%**，人均 **1.77 → 2.42** 颗。」
>
> 「代价：宝石的稀缺感会从'每一颗都独一无二'变成'集齐五色才是目标'——单颗被抢走的痛感会略降。作为交换，全程几乎不再有人空手而归。」

**⚠ 但"10 颗会让冒险不再需要动脑"这个担心，已经被实测推翻了**（这是本轮最有价值的一条反转）：

> 把"买不起就不去"这道检查关掉之后，失败率从 **7.0% 飙到 66.5%** —— 差 **59.5 个百分点**，是噪声的 **50 倍**。**"会算账"这件事在 10 颗配置下非常值钱。**

→ 所以第 2 项真正的取舍不是"要不要动脑"，而是**"你能不能接受约 1/9 的角色空手而归"**。

## 二、这游戏是什么（已确认的玩法，P0.5）

1. 45° 俯视角的迷宫寻宝博弈——4 只呆萌小机器人从迷宫四角出发，抢宝石、开宝箱，在体力耗尽前找到自己的出口。
2. 你控制那只有光环、高饱和配色的机器人，另外 3 只单色机器人由大模型 AI 决策；你的角色也可以完全交给自己写的脚本或提示词 AI 托管。
3. 所有角色每回合同时走一格，走一格消耗一点体力；捡散落的五色宝石拿分，开宝箱赌分数或体力，在体力见底前摸到属于自己颜色的那个出口。
4. 走到自己的出口且分数最高者获胜；没走到出口就是失败；分数相同比剩余体力，还相同则平局。
5. 每一回合都在赌同一件事——多绕一格去捡宝石，还是把最后一点体力留着走回出口。

## 三·补　实测依据（架构仿真，独立两组）

| 实测项 | 数字 | 结论 |
|---|---|---|
| **出口区间** | `[85,100]` 下**连续 20 次重掷全败的概率是 59%**；`[68,108]` 下是 **0%** | 🔴 必修。放宽带 40 步，而墙密度参数引起的漂移只有 ±3 步——**带宽是漂移的 13 倍，不用重校** |
| **出口 carve** | 不 carve 时出口 **100% 不可达**；出生点 `(2,2)` 天然地板率只有 **29%**（不 carve 则七成的局出生在墙里） | carve 是必需的，不是可选优化 |
| **体力加到 450 反而更差** | 单局 **442 回合**（破 320–400 区间），**且失败率反而升高**（9.4% → **11.6%**） | **体力越多 AI 越敢贪，回不了家的人反而更多**——这条把"失败来自贪心、而非走不到出口"从主张变成了实测 |
| **完整对局**（边中点 · 10 颗 · 四人 · 体力 400） | 到达率 **90.6%**（95% CI 下限 **88.7%**）｜人均宝石 **2.52**｜零收获 **5.4%**｜回合中位 **393** | 四项门禁全过（≥85% / ≥1.5 颗 / ≤15% / ≤450 回合）｜⚠ 另有一组独立仿真报 93.0%，**差 2.4 个百分点、超出置信区间宽度**，原因在查（`endgameThresholdFactor` 参数）。**收敛前以 90.6% 为准** |
| **失败率的三个分母**（同一件事三种说法） | actor-局 **9.4%**｜至少一人没回家的局 **22.0%**｜按局均值 **9.4%** | **门禁只认 actor-局口径**（9.4% ≤ 15% ✅）。⚠ 给人解释要用第二个：**约 1/5 的对局会有人倒下**，和"九成的角色能回家"是同一件事 |
| **撒点（旧→新）** | 单人独占可捡 **15.05 → 5.48**｜四人竞争可捡 **4.42**｜集齐五色 **0.5% → 22.0%**｜包围盒 **18 → 123.7 格** | 🔴 **必修项不是优化项**：旧撒点下**游戏被打穿**——单人独占把全场拿光，"抢"这件事根本不存在 |
| **事件触发（语义 bug）** | 「状态型」判定下每 agent 事件 P90 = **80 次**，全局 max 353。元凶：⑥"对手进入视野"被实现成"对手**还在**视野里"——两人抢同一颗宝石时反复触发，而 LLM 每次收到的是**同一份观察** | 🔴 必修。改**边沿型**后 P90 = **10**（降 87%）。事件上限 6→**10**；事件⑦「冲刺窗口」100 局**零触发**，删除 |
| **绕路系数** | 图内部点到点 **1.009**；`spawn→exit` **1.297** | 别按"迷宫"想象：braid 0.35 + 削墙后是**散布 35% 墙的开阔地**；出口在边界自带 ~30% 路径惩罚 |
| **僵持兜底** | 每局触发 **38–103 次** | 救命机制，不是边缘分支 |
| **调用预算** | 总量上限 **360**，拆成**两个物理隔离的池**：常态 **240** / 终盘 **120**；每 agent 常态软上限 **60**（实测 per-agent 最大 **56**，被削比例 **0.0%**） | 旧划分 320/40 的**余量分配是反的**——终盘只余 2 次、常态却余 173 次。⚠ **余量该放在会撑破的那一侧** |

> ⚠ **口径提醒（本轮踩过的坑）**：同一件事在不同脚本/配置下会给出差 1.9 倍的数。
> - **宝石数**：`t2` 跑的是 5 颗配置（人均 2.97），`bench-match` 跑的是 10 颗（人均宝石 2.52）。**5 颗口径的数一律不用于 10 颗结论。**
> - **竞争度**：单人独占可捡 3.59，四人竞争只有 2.97——**差 30 个百分点，别混着看。**
> - **出口方案**：内侧环与边中点各有一套数（零收获 21% vs 13%）。我们采用**边中点**，所以全文只用边中点口径。
> - **统计量**（本轮最贵的一课）：同一个"回到家时还剩多少体力"，可以给出 **41**（中位数）或 **78 / 82**（没标统计量的单点输出）—— **差 1.9 倍**。`78 / 79 / 81 / 82 / 88` 这一整组数已全部撤下、不得引用。**摘数前先看它标的是中位数还是均值。**
> - **生成参数**：`keep = 0.76` 在两套生成器下是**两种不同的迷宫**（墙密度 0.393 vs 0.355）。**所以口径标签一律用"封边后墙密度"，不用参数名。**

## 四、技术方案要点

| 项 | 结论 |
|---|---|
| 渲染栈 | **Canvas 2D 原生、零第三方依赖**（分块 8×8 预烘焙，每帧 ~40 blit）。反悔成本 ≈ 重写 `src/render/` 5 个文件 |
| 迷宫生成 | growing-tree + braid + 削墙（标定到**封边后墙密度 0.355 ± 0.008**）；出口与出生点**必须 carve** 到主连通域（不 carve 则出口 100% 不可达） |
| 性能 | 地图生成+校验 **P95 3.94 ms**（撒点优化后 9.41 → **1.38 ms**）｜1080p ≥58 FPS｜位图 ≤48 MB｜静态资源 ≤4 MB |
| LLM 接入 | 本地 Node 代理，**只监听 127.0.0.1:8787**，Key 绝不进前端；非白名单 Origin 返回 403 |
| LLM 节流 | 每 8 回合重规划 + 事件触发，本地 BFS 执行单步移动。比每回合全调用省 ~85% |
| 调用预算 | 上限 **360**（终盘预留池 **从池内划拨**，不存在额外豁免）｜事件 **10 次/agent/局**｜冷却 ≥3｜**事件用"边沿触发"不用"状态触发"**（状态型会让 P90 从 10 涨到 80） |
| 降级链 | 四层（沿用缓存 → 启发式 → repair → 全局降级），**对局绝不中断** |
| 确定性 | `stateHash` 逐回合相等｜`Math.random` 只在 `rng.js`、`Date.now` 只在 `clock.js`｜RNG 分具名流 |
| 脚本沙箱 | Web Worker，删 `fetch/XHR/WebSocket/importScripts/indexedDB/caches`；`distance()` 只接受视野或记忆内的目标，越权返回 −1；决策超时 **100 ms** 且**必须 warm-up**（否则会稳定误伤每个脚本的第一次决策） |
| 托管降级 | 三类计数器**互斥**，**撞墙不计入**——撞墙是正常玩法，计入会把笨脚本 5 回合就托管掉，等于自废卖点 |
| ⚠ 诚实边界 | 沙箱目标是**防误触 + 可观测 + 可复盘**，不是密码学隔离。真防作弊需权威服务器，与"零后端"纪律冲突，**明确不做** |
| 产品纪律 | 零收集纯本地：无账号、无埋点、无云同步；除模型代理外不联网（CSP 强制） |

**⚠ 硬阻塞**：HY4 的 `baseURL`（含 /v1）、`model id`、鉴权头与前缀——这三项没拿到，P1.5 的 LLM 通道只能先写 mock。

## 六、验收要点（158 条断言 + 11 个坐标级场景）

**历史事故的三个问题，现在都写成了断言：**

| 事故问题 | 现在的可复跑断言 |
|---|---|
| 炸完不消失 | 已拾取宝石仍在渲染的回合数 **= 0**；已开宝箱仍存在 = 0；已达成/失败角色仍在场 = 0 |
| 角色能穿墙 | 200 局回放逐回合校验，落在墙格的次数 **= 0**，坐标恒为整数 |
| 操作不顺畅 | 加速档位生效、单格动画 ≤250 ms、输入→画面 ≤80 ms、连按不丢输入 |

**两条立判据的硬规则**：① 每条"拒绝类"断言必须配**双向对照**（不只测"该拦的拦住了"，还要测"合法的能被放行"）；② 门禁必须核**执行链**（历史上守卫脚本写好了却从没接进 `npm test`）。

**本轮新加的两条**：③ **失败归因分类**——每次失败记 `GREED`（明知回不去还捡）还是 `UNAWARE`（没收到预警就耗尽），后者占比 >20% 判 UI 缺陷；④ **体力约束有效性**——到达者剩余体力 / 初始体力 ∈ **[10%,30%]**，超过 30% 说明体力根本不构成约束、核心取舍消失。

**⚠ 12 条断言覆盖不到、只能你亲手玩**（灰盒闸门交接清单）：

操作跟不跟手 · 方向映射直不直觉 · 一局会不会觉得冗长 · 镜头跟丢 · 一眼分敌我 · 五宝石灰度可辨 · 音效辨识 · 出口罗盘够不够用 · AI 聪不聪明 · 堵位好不好玩 · 遭遇频率 · 特效是否克制

## 九、本轮协作的三条教训（写给你，也写给下一轮）

1. **并行产出必须有仲裁回合**。两位总监同时产出的 P1 文档之间有 10 处数值冲突，其中"对角出口 248~320 步"直接推翻了创意总监整套数值推导的前提。**不能默认两份文档自洽。**
2. **改规则必须复搜，且复搜要覆盖等价表述**。"间隔 12" 和 "每 12 回合一次" 是同一个值，只 grep 一种写法必漏。本轮因此出过一次"漏洞修了却原样复发"。
3. **描述现状时用了过期的判据，会把一个正常的决策包装成一次例外**。我曾写"严格按硬校验，边中点不通过"——但那条校验当时已作废。差别不只是措辞：**例外需要有人点头，规矩不需要**。同一类错误还有反向版本：把某次观测值当成规范挂下来（"失败率不得 >35%"其实是旧配置的观测结果）。**观测 ≠ 规范，猜测 ≠ 门槛。**
4. **拿一个"看起来合理"的量当门槛之前，先确认它和目标量是线性关系**。本轮踩了四次同一类：
   - `×1.15 + 8`（终点阈值带常数项，尺度不守恒 → 改成纯比例 ×1.3）
   - `≤ 6 件`（绝对件数，宝石数一变含义就反过来 → 改成比例 ≤70%）
   - `[85,100]`（拍脑袋区间，实测直接崩 → 放宽到 `[68,108]`）
   - **"重掷率 <5%"**（**非线性量**：实测重掷率 2.8% 与 20.7% 相差 7 倍，但"游戏开不开得起来"的结果完全一样；真正该守的是「**连续 20 次重掷全败的概率 ≤ 10⁻⁶**」）

   最后一例最典型：**它看起来最严谨（是个百分比），实际最没用**，因为门禁守的量（重掷率）和真正关心的量（能否开局）之间不是线性关系。
