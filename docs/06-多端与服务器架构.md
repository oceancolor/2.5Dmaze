## 0. 一句话

最终交付形态是 **客户端（Web / H5 / 桌面）+ 游戏服务器**。服务器负责：

1. **记录全部对战数据**（权威存档 + 重放校验）；
2. **AI 中转与 Agent 网关**：玩家的大模型 key 与外部 Agent 都接到服务器上，费用**谁用谁付**；
3. **对局宿主**：需要服务器参与决策的对局（外部 Agent 代打，以及未来的玩家对局）由服务器来跑；
4. **为玩家对局（PvP）预留**：本期不做 PvP，但架构、数据表和接口不能挡路。

## 1. 旧约束：推翻什么、保留什么

| 旧约束（出处） | 现在 | 说明 |
|---|---|---|
| 无后端、无账号、零埋点（02 A7）；「零后端纪律」（00、02 §8） | **推翻**（U7） | 有服务器、有（游客）账号、记录对局数据。不做行为埋点，只记对局本身 |

| 密钥不进前端 | **保留** | key 只交给服务器，网页不保存（05 §7.2） |
| 确定性内核 + 严格回放 | **保留并升级为基石** | 同一份内核跑在客户端、服务器宿主、服务器校验三处；多端同步也靠它（§3） |
| 零第三方依赖 | 网页客户端**保留**；服务器 S0–S2 **保留**；**Electron 壳例外** | 服务器用 Node 内置的 `node:http` / `node:sqlite` / `node:crypto`，推送用 SSE，PvP 规模化时再评估（Q14）。Electron 壳放在独立目录 `desktop/`，有自己的依赖清单；主仓库的 `npm test` 和网页、服务器仍然不需要 `npm install`（§8.2） |
| 离线可玩 | **保留** | 手打 / 脚本 / 模拟大模型不联网也能玩；记录联网后补传 |

## 2. 总体架构

```
 ┌───────────── 客户端（同一份前端代码：index.html + src/）──────────────┐
 │  Web（桌面浏览器）   H5（手机浏览器 / 微信内）   桌面（Electron 壳）      │
 │                                                                     │
 │  本地宿主：内核 + 调度器 + 规划 agent 在客户端跑（手打 / 脚本 / 模拟 / 自带模型）│
 │  远程观战：订阅服务器对局流，用本地内核锁步重算、渲染（外部 Agent / PvP）     │
 └──────────────┬──────────────────────────────┬────────────────────────┘
                │ HTTPS：/api/v1  /llm/v1        │ SSE：对局流（下行） + POST：输入（上行）
 ┌──────────────▼──────────────────────────────▼────────────────────────┐
 │  游戏服务器（Node，单进程起步）                                          │
 │   api        游客账号 · 对局上传 / 查询 · key 管理 · 用量                   │
 │   verifier   上传记录 → 用同一内核重放 → verified / mismatch               │
 │   host       服务器宿主：跑对局（内核 + 调度器 + 规划 agent），推 SSE 流      │
 │   agent-gw   /agent/v1：外部 Agent 取局面、交决策（05 §6.3）               │
 │   llm-relay  /llm/v1：带上「这位玩家自己的 key」转发到服务商                  │
 │   vault      key 加密保管      store  SQLite（WAL）                       │
 └──────────────┬──────────────────────────────▲────────────────────────┘
                │ HTTPS（玩家的 key）            │ HTTPS（对局口令）
          大模型服务商                     玩家电脑上的 Agent（用它自己的模型）
```

## 3. 核心机制：同一个确定性内核跑在三处

### 3.1 本地宿主 + 上传校验

- 和现在一样：对局在客户端跑，结束后把 JSONL 记录上传。
- 服务器用**同一份内核**按 `seed + 每回合意图` 重放，逐回合比对 `stateHash`：一致 → `verified`；不一致 → `mismatch`（记录照存，但不进任何统计 / 排行）。
- 离线时记录进客户端队列（IndexedDB），联网后补传；`matchId` 由客户端生成（随机 128 bit），重复上传幂等。

### 3.2 服务器宿主 + 锁步观战

- 对局在服务器跑。服务器把**记录行本身**（`meta` / `turn` / `plan` / `end`，即 SPEC §12 的格式）通过 SSE 推给客户端。
- 客户端用本地内核对每个 `turn` 行执行 `step()`，得到完整状态和事件来播动画，并核对 `h`：
  - 带宽极小：每回合约 45 字节；
  - 不同步当场发现（哈希不一致 → 重新拉流）；
  - 断线重连 = 从第 n 回合起重新订阅（`?from=n`）。
- **节奏**：服务器没有动画，会瞬间跑完两次决策之间的几十个回合，画面就落后于「AI 正在想」的提示。所以服务器宿主**按观战倍速推进**（默认 2×，约 1 回合 / 220 ms），画面与服务器状态同步；房主可以改倍速或「跳到结算」（PvP 时节奏固定）。

### 3.3 哪种对局在哪跑

| 对局类型 | 宿主 | 能否离线 | 记录可信度 |
|---|---|---|---|
| 手打 / 脚本 Agent / 模拟大模型代打 | 客户端 | 能 | 规则合法（重放校验） |
| 自带模型代打（05 模式 B） | 客户端（M1）；S1 之后可选服务器 | 否（要中转） | 规则合法；另可核对计划行与服务器的中转调用日志 |
| 外部 Agent 代打（05 模式 A） | **服务器** | 否 | 服务器权威 |
| 玩家对局（PvP，未来） | **服务器** | 否 | 服务器权威 |

### 3.4 前提：共享代码必须「同构」

`src/core`、`src/ai`、`src/record`、`src/app/scheduler.js` 同时运行在浏览器和 Node：

- 不得引用 `window` / `document` / DOM；时钟一律注入（现有确定性 lint 已管住 `Date.now` / `Math.random`）；
- 新增 `tools/lint-isomorphic.mjs`，接进 `npm test`；
- 验收 V08：同一 seed、同一组意图，客户端宿主与服务器宿主产出**逐字节相同**的记录。

## 5. 账号与身份

- **S0 只做游客账号**：客户端首次联网时调用 `POST /api/v1/guest`，拿到 `userId + token`，存在本机（Web 用 localStorage，桌面用应用存储）。昵称可选。
- 请求一律 `Authorization: Bearer <token>`，Web、H5、桌面、Agent 网关同一套。数据库只存 token 的 SHA-256。
- 换设备、找回、PvP 身份需要正式登录。**Q9 裁定**：S0–M3 只做游客账号；正式登录在 PvP 之前做，届时优先微信 + 手机号。
- 游客数据可一键导出、删除。

## 6. 对战数据记录

### 6.1 存什么（SQLite）

| 表 | 主要字段 |
|---|---|
| `users` | id、kind（guest / bound）、nickname、token_hash、created_at |
| `matches` | id、user_id、host（local / remote）、platform（web / h5 / desktop）、client_version、rules_version、config_hash、seed、map_hash、started_at、ended_at、turns、ranking_json、seats_json、verify（verified / mismatch / unverifiable）、verify_note |
| `match_records` | match_id、jsonl_gz（整局记录，压缩后约 10 KB） |
| `seat_stats` | match_id、seat、source（manual / script / mock / heuristic / byok / agent-external）、model、decisions、follow / partial / override / invalid / gate 计数、tokens_in / tokens_out、延迟 P50 / P95 |
| `strategies` | match_id、seat、autonomy、hard_json、text（玩家思路原文，**仅本人可见**） |
| `keys` | id、user_id、provider、base_url、model、enc_key、iv、tail4、created_at、last_used_at |
| `usage` | user_id、match_id、provider、model、tokens_in、tokens_out、at |

体量：一局记录原文约 45 KB，压缩后约 10 KB；100 万局约 10 GB。单机 SQLite 足够撑过 v1。

### 6.2 不存什么

- API key 明文、对局口令明文、用户 token 明文；
- 客户端行为埋点（点击、停留等）；
- 外部 Agent 的 `memo` 只存在本人私有记录里，每局有上限（500 字 × 决策上限 80）。

### 6.3 能验证什么、不能验证什么（诚实边界）

| | 本地宿主（上传校验） | 服务器宿主 |
|---|---|---|
| 规则合法（没有穿墙、没有凭空加分） | ✅ 重放校验 | ✅ |
| 结果确实由这串意图产生 | ✅ | ✅ |
| 意图真的来自声明的来源（人手 / 某个模型） | ❌ 无法证明（可能是外挂脚本代打） | ✅ 服务器知道每个座位的输入从哪来 |
| 没有偷看视野外信息 | ❌ | 单人：观战流是完整状态，同一账号的客户端理论上能看到；PvP：改为按座位过滤（§10） |

因此：本地对局可以进**个人战绩**；任何「排行榜」只收服务器宿主的对局。

### 6.4 规则版本

服务器同时保留「当前 + 上一个」`rulesVersion` 的内核快照（`server/kernels/<rulesVersion>/`）。更早版本的记录照存，标为 `unverifiable`。客户端版本过旧时，上传和开服务器局都返回明确的「请更新」错误。

### 6.5 隐私与保留

- 思路原文、memo 仅本人可见，不公开、不用于训练；统计分析只用聚合数。
- 保留期待定（Q12）。建议：游客 180 天不活跃清理；正式账号长期保留，可随时删除。
- 上线前要有隐私说明（个人信息保护法：最小必要、可删除）。

## 7. AI 中转与费用：谁用谁付（Q3 裁定）

### 7.1 规则

- **服务器从不为任何人的模型调用付费。** 每一次大模型调用都归属到一个用户，用的是这个用户自己的 key。
- 玩家自己的 AI（05 模式 B）：用玩家的 key。
- 对手 AI 用真模型（包括 HY4）：这是开局玩家选的，所以也用**这位玩家**的 key（**Q11 裁定**）。开局页明示「3 个真模型对手，费用约为只有你自己用 AI 时的 4 倍」。默认对手是模拟大模型 / 启发式，免费。
- 外部 Agent（05 模式 A）：用玩家 Agent 自己的模型，服务器只做网关，不产生模型费用。
- PvP：每位玩家各自付自己 AI 的费用。

### 7.2 key 怎么保管

- 网页只在提交时经 HTTPS 发一次 `POST /api/v1/keys`，然后立刻清空输入框；网页不保存、不回显。
- 默认「仅本次会话」：只放在服务器内存里，会话结束或 24 小时后丢弃。
- 勾选「记住」：用 AES-256-GCM 加密后入库，主密钥来自环境变量 / KMS，不进库、不进仓库。
- 任何接口都不返回明文，只返回服务商、模型名和尾号（如 `sk-…3f9a`）；日志打码；用户可随时删除。
- 桌面端（Electron，§8.2）可选「本机直连」：key 用系统钥匙串加密存在本机，由壳的主进程直接调用服务商，不经服务器，网页部分也拿不到 key。

### 7.3 中转的安全

- **服务商白名单**：预设服务商的地址写死在服务器配置里。
- **自定义地址防 SSRF**：只允许 `https://` + 443 端口；DNS 解析后拒绝内网、回环、链路本地、云元数据地址（如 `169.254.169.254`）；每次连接都按解析结果校验。
- 本机模型（Ollama 等）服务器够不着，只在桌面端的「本机直连」里可用。
- 中转只接受「属于本人、正在进行的对局」的请求；按用户和 IP 限频，防止被当成公共代理。
- 服务器部署在中国大陆时，海外服务商（如 OpenAI）可能连不通，设置页如实提示。

### 7.4 用量

从服务商回复的 `usage` 字段记录 token 数，结算卡和「我的」页面展示「本局 / 本月 用了多少 token、约多少钱（按服务商公开单价估算）」。玩家可以设每局调用上限，由规划 agent 的预算池执行。

## 8. 多端客户端

### 8.1 三端对照

**同一份前端代码**；平台差异只在输入、布局、存储和外壳。

| | Web（桌面浏览器） | H5（手机浏览器 / 微信内） | 桌面（Electron） |
|---|---|---|---|
| 现状 | 已可玩 | 待适配 | 骨架已落地（§13.3） |
| 输入 | 键盘（现有） | **触屏**：虚拟方向盘 + 滑动；长按连走；双指缩放、拖拽平移 | 键盘 |
| 布局 | 四角 HUD | 竖屏：HUD 折叠为顶栏 + 底部抽屉；横屏沿用四角 | 同 Web |
| 性能 | 现有降级链 | 默认画质降一档、DPR 上限 2、低内存设备用 1× 图集 | 同 Web |
| 外部 Agent（模式 A） | ✅ | ✅（Agent 在电脑上跑，手机上观战） | ✅；另可选离线本机对局（§8.2） |
| 自带模型（模式 B） | 经服务器中转 | 经服务器中转 | 经服务器中转，或本机直连（含 Ollama 等本机模型） |
| 脚本 Agent | ✅ | 能用，但不推荐在手机上写代码 | ✅ |
| 离线 | 本地对局可离线 | 同左 | ✅ |

H5 另做一个 Web App Manifest，支持「添加到主屏幕」（并入 C1，不单独成期）。

### 8.2 桌面端：Electron 壳（Q10 裁定）

**为什么要壳**：网页做不到这三件事——① key 存进系统钥匙串、由本机直接调用服务商；② 调用本机模型（Ollama 等）；③ 断网时用自己的 Agent 打（壳在本机起网关）。外加安装包、桌面图标、自动更新。

**结构**

```
desktop/                  独立目录，自带 package.json（electron、electron-builder 等只在这里）
  main.mjs                主进程：窗口、app:// 协议、IPC、自动更新
  preload.cjs             通过 contextBridge 暴露最小接口 window.mazeDesktop
  local/                  本机能力：钥匙串 vault、直连 transport、离线网关（复用 server/host 与 agent-gateway）
  build/                  图标、安装器配置
```

- **同一份前端代码**：打包时把 `index.html`、`src/`、`assets/` 原样拷进安装包。网页通过 `window.mazeDesktop` 是否存在判断自己是否在桌面端，再打开对应功能。
- **加载方式**：注册自定义安全协议 `app://maze/`，以「标准 + 安全」权限加载。**不用 `file://`**：ES 模块、Worker 和 CSP 在 `file://` 下行为不一致，L13 也要求零 `file://` 加载失败。CSP 由协议处理器在响应头下发，与 Web 版相同，另加 `connect-src https://maze.aiquiz.games`。
- **安全基线**（每个窗口都必须满足，V11 自动检查）：
  - `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true`；
  - 渲染进程只能用 preload 暴露的几个函数（列出 / 保存 / 删除 key、直连调用、本机网关开关、版本信息），不能直接接触 Node 或文件系统；
  - 禁止窗口导航到外部地址；外部链接一律用系统浏览器打开；
  - 不加载任何远程代码：游戏代码只来自安装包，更新走自动更新。
- **本机直连（模式 B）**：
  - key 由主进程用 Electron `safeStorage` 加密后存在用户目录（Windows 用 DPAPI，macOS 用钥匙串，Linux 用系统密钥环）；
  - 决策请求从网页经 IPC 交给主进程，主进程附上 key 再调用服务商，所以**网页部分始终拿不到 key**（「密钥不进前端」照样成立）；
  - 服务商白名单与 SSRF 规则同 §7.3，另外放行 `http://127.0.0.1:*` 和 `http://localhost:*`（本机模型）；
  - 直连产生的 token 用量在本机统计，随对局记录上传。服务器不经手这些调用，所以只能记录客户端自报的数字（标为「自报」）。
- **离线本机对局（模式 A，可选，C3）**：主进程用同一套服务器宿主代码（`server/host` + `agent-gateway`，同构，§3.4）在 `127.0.0.1` 的随机端口上跑对局，卷轴里的地址换成本机地址。对局记录联网后补传，标为 `host=desktop-local`，可信度按「本地宿主」算（§6.3）。
- **自动更新**：`electron-updater`，更新源 `https://maze.aiquiz.games/desktop/`。
  - 客户端版本过旧时，服务器返回「请更新」（V07），壳收到后提示一键更新；
  - 下载的安装包必须带有效签名才安装。
- **代码签名**：
  - Windows 没有签名会被 SmartScreen 拦截提示，需要代码签名证书；
  - macOS 需要 Apple 开发者账号签名并公证，否则无法正常打开；
  - 先做哪个平台、证书由谁申请，见 Q16。
- **体积**：安装包约 80–120 MB（主要是自带的 Chromium 内核），不计入 K11 的 4 MB 网页资源预算；网页资源本身仍受 K11 / K12 约束。
- **Electron 版本**：锁定一个仍在官方支持期内的大版本，跟随安全更新；每次升级大版本都要重跑 V11。

## 9. 外部 Agent 网关搬到服务器（对 05 的影响）

- 网页无法在本机监听端口，所以 Web / H5 要支持模式 A，网关**必须在服务器上**：`https://<服务器>/agent/v1/*`。
- 对局由服务器宿主运行；Agent 直接与服务器对话，浏览器只观战。
- 口令只授权「这一局的这一座位」，开局后其他口令一律拒绝。
- **Q2 裁定**：只支持在玩家电脑上运行的 Agent。云端运行的 Agent 不做适配、不做测试、不承诺可用。
- **Q8 裁定**：不做「关掉浏览器继续打」功能。服务器宿主下，对局本来就不依赖浏览器，刷新后重新订阅即可继续观战，不需要额外工作。

## 10. 为玩家对局（PvP）预留（本期不做）

PvP 另写设计文档。现在先定下不能挡路的几件事：

| 方面 | PvP 需要 | 现在怎么预留 |
|---|---|---|
| 宿主 | 只能服务器宿主 | S1 的宿主从一开始就支持「每个座位来自不同连接」 |
| 回合等待 | 不能无限等某一个人（与 SPEC §9.1「手打无超时」冲突） | PvP 单独加回合时限（如 8 s，超时原地等；连续 3 次超时 → 启发式托管），单人模式不受影响 |
| 信息隐藏 | 锁步推完整状态会泄露视野外的对手位置 | PvP 改为按座位推送过滤后的观察（`observe()`）；渲染器要能只画已知信息 |
| 断线 | 不能拖死整局 | 断线 → 启发式托管；重连从第 n 回合恢复 |
| 身份 | 正式账号 | §5，PvP 前上线 |
| 房间 | 私人房间码先行，匹配后做 | `rooms` 模块与表结构预留 |
| 排行 | 只收服务器宿主的对局 | §6.3 |

## 12. 部署与运维

### 12.1 域名与入口（Q13 裁定：域名 `aiquiz.games` 已备案，用自有云主机）

- **建议用子域名 `maze.aiquiz.games`，单一来源**（Q17 已裁定）：游戏静态文件、`/api/v1`、`/llm/v1`、`/agent/v1`、SSE 对局流都挂在同一个 HTTPS 地址下。
  - 浏览器全部同源请求，Web / H5 不需要处理跨域；
  - 卷轴里给 Agent 的地址就是 `https://maze.aiquiz.games/agent/v1`；
  - 将来别的游戏用 `aiquiz.games` 的其他子域名，互不干扰。
- 跨域只放行两个来源：`https://maze.aiquiz.games` 和 Electron 壳的 `app://maze`。
- 上线前检查：
  - 云主机所在的云厂商，必须与 ICP 备案的接入商一致；不一致需要先做接入备案；
  - 网站底部按要求展示备案号。

### 12.2 运行

- **进程**：单个 Node 进程（Node ≥ 22.13，用于内置 `node:sqlite`；22.17 已实测可用，会打印实验特性警告）。生产环境锁定 Node 版本，用 systemd 托管、崩溃自动重启。
- **存储**：SQLite 开 WAL，每日备份到云主机之外（对象存储或另一块盘）。
- **配置**：全部走环境变量：`PUBLIC_ORIGIN=https://maze.aiquiz.games`、`DB_PATH`、`MASTER_KEY`、`PROVIDERS`。`MASTER_KEY` 不进仓库、不进数据库。

### 12.3 反向代理（Nginx / Caddy）

- 负责 HTTPS 终结、证书自动续期、HTTP 跳转 HTTPS。
- **SSE 对局流**：关掉代理缓冲（Nginx：`proxy_buffering off`），否则回合会被攒成一批才推下去。
- **长轮询** `/agent/v1/wait`：读超时 ≥ 60 s。
- 请求体上限：64 KB；对局记录上传 1 MB。

### 12.4 安全与合规

- 跨域白名单见 §12.1；客户端 CSP `connect-src 'self'`（桌面壳另加服务器地址）。
- 按用户 / IP 限频；日志打码。
- 有用户数据，需要隐私说明（个人信息保护法：最小必要、可删除）。

### 12.5 本地开发

- `npm run play` 改为在本机起服务器的开发模式：同时托管静态文件，SQLite 存在 `.data/`。一条命令即可开发和试玩，`PUBLIC_ORIGIN` 默认 `http://127.0.0.1:5173`。
- `tools/serve.mjs` 保留为纯静态预览。

### 13.1 S0 实现说明（2026-10-29）

- **规则版本**：S0 只带当前内核（`SPEC-0.1`）；规则版本不同的记录照存、标 `unverifiable`。§6.4 的「当前 + 上一版」内核快照在规则第一次升版时再建 `server/kernels/`。
- **配置识别**：服务器为每种玩家通道（manual / prompt / script）各算一份 configHash；记录的 configHash 不在其中 → `mismatch`（第 0 回合）。
- **排名以服务器为准**：通过校验的对局，入库的排名是服务器回放重算的；客户端声称的排名与之不符也判 `mismatch`。
- **统计口径**：`seat_stats` 只写 `verified` 的对局。
- **身份边界**：别人的对局一律 404（不泄露是否存在）；同一 `matchId` 被别人或另一份内容占用 → 409。
- **限频默认值**：每 IP 每分钟 240 次 API；创建游客每 IP 突发 10、之后每分钟 2；上传每用户每分钟 30。
- **客户端**：结算卡显示上传 / 校验结果；设置页「我的战绩」显示最近 10 局。静态预览（`tools/serve.mjs`）的 `/healthz` 返回 `api:false`，客户端据此静默跳过同步。
- **离线限制**：页面本身还不能离线打开（没有离线缓存，桌面端由 Electron 壳解决）；页面已打开时断网，手打 / 提示词 / 启发式照常可玩、记录联网后补传。但脚本 Agent 的沙箱 Worker 要从网络加载，断网后开新局会提示「脚本无法加载」。

### 13.2 M1 实现说明（2026-10-29）

- **key 的去向**：设置页的 key 输入框只在点「保存并测试」时读一次，经 `POST /api/v1/keys` 发给服务器后立刻清空；设置对象、localStorage、IndexedDB、记录里都没有它。开局和中转请求里只有 `keyId`（服务器上那把 key 的编号）。
- **两种保管**：默认「仅本次会话」，只在服务器进程内存里，24 小时或服务器重启后丢弃；勾「记住」则 AES-256-GCM 加密入库，AAD 绑定用户与行，主密钥来自 `MASTER_KEY`（开发模式自动生成 `.data/master.key`；生产不设则「记住」不可用）。每人最多 10 把。
- **服务商预设**：腾讯混元 HY4（`tokenhub.tencentmaas.com/v1`，`hy4-preview`，默认关闭思考，**已实测**）、DeepSeek、火山方舟、阿里云百炼、Moonshot、OpenAI、自定义（OpenAI 兼容）。除混元外都只按公开文档配置，未用真 key 验证。
- **中转边界**：中转只认本人的 key；请求必须带 `matchId` 与座位，消息 1–4 条、合计 ≤ 32000 字符；每用户突发 60、每分钟 180 次；每个 `matchId` 最多 1600 次。服务器在对局结束上传前并不知道这局存在（本地宿主），所以做不到「只接受进行中的对局」——限频和每局上限是替代手段，S1 服务器宿主后可以收紧。
- **超时**：客户端 40 s（推理模型 85 s）、服务器等上游 45 s（90 s）、Nginx 读超时 100 s。HY4 关闭思考实测经中转两局 39 次：P50 ≈ 2.9 s、P90 ≈ 4.5 s，最慢 24.9 s。客户端先放弃的那次，服务器仍等上游回来并记账（服务商照样计费），所以超时宁长勿短。
- **用量**：每次经服务器的调用（含测试连接、失败）记一行 `usage`；token 取服务商回复的 `usage` 字段。结算报告与对局详情里的 token 以服务器账本为准（客户端改不了）。**没有做金额估算**：各家单价常变，先只显示调用次数和 token 数。
- **玩家思路**：原文随上传进 `strategies` 表，只有本人的详情接口返回；记录 `meta.players` 里只有它的 FNV-1a 哈希、服务商、模型名、自主度、闸门开关。
- **座位统计**：`seat_stats` 加模型名、决策数、遵循 / 部分 / 偏离、不合格、token（仍只写 `verified` 的对局）；计划行由记录自报，只作复盘，不影响校验结论。

### 13.3 C2 桌面端实现说明（2026-10-29，骨架已落地）

按用户裁定「桌面端提前」，S1 / M2 之前先做了 Electron 壳的骨架。独立目录 `desktop/`（自带 `package.json`，Electron 44.10.0 在官方支持期内；`electron`、`electron-builder`、`playwright-core` 只装在这里，主项目仍是零依赖）。

- **同一份前端**：`src/app/sync.js` 判到 `window.mazeDesktop` 时，接口请求自动改带 `mazeDesktop.serverOrigin` 绝对地址（页面在 `app://maze` 下，与服务器不同源）；Web / H5 不变，用相对路径。这是唯一为桌面端改的共享前端文件。
- **加载**：`app://maze/` 注册为「标准 + 安全」协议，路径白名单与 CSP 复用 `server/static.mjs` 导出的 `isPublicPath` / `gameCsp`（`connect-src` 另加游戏服务器地址）；不用 `file://`。
- **安全基线（V11）**：`contextIsolation`/`sandbox` 开、`nodeIntegration` 关、`webSecurity` 开、`webviewTag` 关；导航 / 重定向 / 新窗口到外部一律拦截并交给系统浏览器；所有权限请求默认拒绝（仅开发时放行连本机服务器）；IPC 只接受来自 `app://maze` 页面的调用。`desktop/tools/e2e.mjs` 真启动 Electron 冒烟验证：窗口加载、`window.mazeDesktop` 注入、渲染进程拿不到 `require`/`process`、跨域 `/healthz` 连通，全部通过。
- **跨域 CORS**：服务器默认 CORS 白名单含 `app://maze`；`/healthz` 对白名单来源回 `Access-Control-Allow-Origin`；`/api/*`、`/llm/*` 的 OPTIONS 预检返回 204 并放行 `Authorization`/`Content-Type`/`X-Maze-Client`。`tests/server.test.mjs` 的 V05 用例固化了这条 Web 版从不走的路径。
- **本机直连（模式 B，V12）**：`desktop/local/` 下的 `vault.mjs`（safeStorage 加密入库 / 仅本次运行只在内存）、`direct.mjs`（地址校验：https 公网上加放行 `http://127.0.0.1:*` 本机模型如 Ollama；上游调用复用 `server/llm-relay.mjs`；用量按月记在本机）、`update.mjs`（自动更新策略）。`preload.cjs` 只暴露最小接口，网页拿不到 key。
- **自动更新**：`electron-updater` generic 源。**签过名的版本**才自动下载安装（安装前校验签名）；未签名版本只提示并打开下载页，绝不自动安装。证书到位后把 staged `package.json` 的 `mazeSigned` 设为 true 即可。
- **打包**：`npm run icon`（Pillow 从图集裁玩家精灵生成图标）→ `npm run stage`（把前端 + 服务器运行时代码按仓库布局拷进 `.stage/`）→ `npm run dist`（electron-builder 出 Windows NSIS 安装包）。签名证书未到位，安装包未实际构建。
- **测试**：`desktop/tests/local.test.mjs` 8 个用例覆盖地址规则、key 保管、直连调用与更新策略，随主 `npm test` 一起跑（107 全绿）。

**还没做的**：V12/V13 的真机校验（本机直连一整局、桌面端与 Web 记录逐字节比对）、Windows 安装包实构建与代码签名、C3 桌面离线本机对局、e2e 自动化接入 CI（需能开图形窗口的会话）。
