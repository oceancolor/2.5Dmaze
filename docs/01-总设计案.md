## ⚠ v1.1 修订（基于技术架构总监实测仿真：300 种子 / 200 局）

实测推翻了 v1.0 对**出口位置**的假设。以下以 **v1.1 为准**：

| 项 | v1.0（估算） | **v1.1（实测）** | 修订原因 |
|---|---|---|---|
| 出口位置 | 四条边中点，对角远侧分配 | **内侧环**：以地图中心为圆心、欧氏半径 ~45 格的环上，与出生角一一对应 | 对角实测 248–320 步，光走到出口就吃掉 60%+ 体力，几乎必败 |
| spawn→exit 最短路径 | 200–260 | **89（最大 98）** | 实测值 |
| 墙密度 | 30% ± 3% | **0.355** | 采用实测生成器的真实密度 |
| 绕路系数 D 校验 | 1.20–1.35 | **废弃**，改用路径长度硬校验 | 实测 D 达 1.3–2.4，原目标不可达；直接校验结果更可靠 |
| 体力 | 400 | **400（不变）** | 实测验证：93% 局面捡到 ≥3 个宝物，仅 16% 被单人通吃<br>⚠ 该 16% 是 **≥5 件宝物**口径，**真"拿齐五色"只有 0.5%**，两者差 30 倍 —— 见 §4.2「口径警告②」 |
| 同格冲突仲裁 | 轮转优先级 | **双方都不动**（撤回 v1.0） | 物理直觉更强、代码更简单、强化卡位战术；确定性等价 |
| 主动停留耗体力 | 未定义 | **扣 1**（被阻挡扣 0，四面全阻扣 0）→ ⚠ **四面全阻在 v1.3 已改为扣 1**，本行仅记录 v1.1 当时的值 | 杜绝无限拖延，让"卡位"成为有代价的战术 |
| 宝箱 | 不重生 | **重生 2 次，间隔 ≥ 60 回合** | 中后期需要 rendezvous 锚点，否则全场只剩宝石一个目标 |
| maxTurns | 400 | **600** | 静止耗体力后自然收敛于 ~400 回合；600 仅极端兜底 |

## ⚠ v1.3 修订（QA 过程审核退回后 · 补漏洞 + 钉死冲突项）

| 项 | v1.2 | **v1.3（终稿）** | 理由 |
|---|---|---|---|
| **僵持兜底**（补漏洞） | 无 | **任一角色连续 ≥3 回合未位移 → 第 4 回合起，未位移的回合一律扣 1**（覆盖"被挡扣 0"） | v1.2 的规则存在一个双方都扣 0 的永久僵持：A 在死胡同口被 B 堵住（A 四面全阻扣 0），B 想进 A 的格被挡（扣 0）→ 双方都不掉体力，只能靠 maxTurns 兜底。**加了这条之后，任何僵持都在 ≤403 回合内由体力耗尽终结** |
| **四面全阻扣体力** | 扣 0 | **扣 1** | "四面全阻"在连通迷宫里只可能是被**角色**堵死（墙围死的死角不可能存在），所以它就是僵持的一部分，不该免费 |
| **卡位战术定位** | 未定义 | **不主推、不禁止、不做特殊处理**（不写教程、不做引导、不设"让路"规则）；代价结构刻意做成**对发起方亏本** | 见下方专项 |
| **X10 重规划事件** | 我的 5 类 / 架构 5 类（内容不同） | **统一为 6 条 + 1 条可选**（见 §4.7） | 两份文档内容完全不同，QA 无法断言 |
| **X11 终盘阈值** | 动态 `d(→出口) × 1.3` | **确认 1.3**，架构的 `×1.15 + 8` 作废 | 1.3 是**纯比例、尺度无关**（d 从 10 到 200 都给 30% 余量）；`+8` 是绝对常数，d=10 时余量 95%、d=200 时只剩 19%，两端都不对 |

### 卡位战术的定位（主程序 / QA 请按此理解）

**不是我们主推的玩法，但它是走廊地形的自然产物。不禁止，也不为它做任何特殊处理。**

| 问题 | 结论 |
|---|---|
| 是有效战术吗？ | **是，但刻意做成亏本买卖**：堵人者行动或停留都扣 1，被堵者扣 0 → 堵人纯粹失血，除非能换来一颗决定胜负的宝石 |
| 要写教程 / 做引导 / UI 提示吗？ | **不要**。它是自发行为，不该被教 |
| 需要"让路"规则吗？ | **不需要**。代价结构已经让它自我限制 |
| 会 griefing 吗？ | **不会**。被堵方扣 0，堵人无法饿死对手 |
| 会死锁吗？ | **不会**。加上"连续 3 回合未位移 → 第 4 回合起扣 1"后，任何僵持都在 ≤403 回合内由体力耗尽终结，maxTurns=600 只是第二道保险 |
| QA 断言怎么写 | **任意初始构型下，不存在"双方体力均 > 0 且连续 10 回合双方都未位移"的状态** |

## ⚠ v1.4 修订（X13 改选 A，撤回 v1.3 的 360）· ⚠ **本节已被 v1.7 推翻，仅作历史，不得引用其值**

> **不加这行，下一个人翻到 v1.4 会把 240 当现行值** —— 这正是维护约定第 3 条要防的事。

| 项 | v1.3 | **v1.4（终稿）** | 理由 |
|---|---|---|---|
| 单局 LLM 调用上限 | 360 | **240**（撤回 360） | — |

### 失败率是"决策者有多贪"的函数，不是体力的函数

| 策略 | 终盘阈值 | 四人失败率 |
|---|---|---|

| 激进贪心 | ×1.0（无余量） | **56.4%** |

→ 采纳主理人终裁：**90% 这条只约束引擎侧**。引擎侧到不了家 = **体力配错（配置缺陷）**；玩家侧到不了家 = **决策者选择了贪（博弈结果，正是本作想要的失败方式）**。塞进同一个门槛，等于要么逼着抬体力迁就玩家乱走、要么把玩脱判成 bug。

## 维护约定（防止同一数值在多处不一致）

**根因**：同一个数值散落在多张表里，改一处容易漏其他处。**已经发生过三次**：§5.0 阶段 5 的"四面全阻 -0"、v1.1 历史表的"四面全阻扣 0"、数值总表的"间隔 ≤12"。三次都是同一类：**正文改了，别处的镜像没跟上。**

**约定（我选的是"正文裁定 + 总表镜像"，不用"总表唯一出处"——因为理由必须和值放在一起，主程序和 QA 需要看到为什么是这个数）：**

1. **正文是裁定处**（写「值 + 理由」）；**数值总表是镜像**（只写值，不重复理由）。
2. **改任何数值的最后一步 = 回到数值总表同步**。没有这一步，就不算改完。
3. **历史修订表（v1.1–v1.6）只记录当时值，不参与实现**。读到旧值时以最新版本为准；历史表里的旧值**不得**被当作现行值引用（v1.1 那行已按此加注；**v1.4 整节已被 v1.7 推翻，已在标题加注**）。
4. **被推翻的整节必须在标题上标"仅作历史"**，不能只在正文里说。理由：主程序和 QA 是**按标题扫文档**的，正文里的一句说明救不了一次误引。

**改完必做的复搜 · 4 个高危位置**

| # | 位置 | 查什么 |
|---|---|---|
| 1 | 正文裁定表（§4.x） | 新值与旧值是否并存 |
| 2 | **§5.0 结算顺序表**（主程序照它写代码） | 阶段 2 / 阶段 5 的扣值 |
| 3 | 需求清单（§六） | 验收标准里嵌的数字 |
| 4 | **数值总表**（文末，最容易忘） | 全部数值逐行对 |

**复搜必须覆盖多种写法**：阿拉伯数字（`12`）、中文（`十二`）、符号（`> 12` / `≤ 10`）、带单位（`12 回合`），以及**等价表述**（"间隔 12" 与 "每 12 回合一次" 是同一个值）。

## 一、核心设计概览

| 项 | 内容 |
|---|---|
| 一句话定位 | 45° 仿 3D 俯视角、art deco 低饱和马卡龙风格的 128×128 迷宫竞速博弈：4 只呆萌小机器人从四角出发，抢宝石、赌宝箱，在体力耗尽前冲进自己的彩色出口 |
| 品类 | 回合制同步步进 · 不完全信息博弈 · 单局竞速 |
| 核心动词 | **走**（一格一格推进）/ **抢**（与三个对手争同一批宝石）/ **赌**（绕路换分 vs 保体力）/ **堵**（占位让对手绕行） |
| 目标体验 | 每一回合都在做同一个取舍：**这一步是朝出口，还是朝宝石** |
| 单局时长 | **320–400 回合**（体力 400 全耗完即 400 回合），目标实机 4–7 分钟 |
| 玩家角色 | 4 号位中 1 个：有光环 + 高饱和配色；其余 3 个为单色 poker face AI |
| 玩家操控通道 | 三选一：手工键鼠 / 自制 JS 脚本（沙箱 Worker）/ 自定义提示词交 AI 托管 |

**视野模型裁定（对应"迷雾不要"）**

| 候选方案 | 结论 | 理由 |
|---|---|---|
| 1. 地形全公开，仅动态实体受视野限制 | ✅ **采用** | 用户否掉的是"未探索全黑、走过要重摸"的战争迷雾；地形公开符合"四角色信息对等"。且地形静态 → 寻路交给 BFS，LLM 不必在 16384 格里做逐步寻路（那是最不可靠、最容易翻车的用法），让它专注博弈：目标选择、体力预算、对手意图推断、堵位 |
| 2. 视野半径 + 已探明地形永久记忆 | ❌ 否掉 | 探索本身不是本作玩法（用户已否），且会让 LLM 输入里塞进大量无用地形扫描，浪费 token 还降决策质量 |
| 3. 全公开无视野限制 | ❌ 否掉 | 四角色位置全透明 → 抢宝石与堵位博弈全部消失，退化为各自 BFS 竞速 |

**但"地形全公开"不等于"把 16384 格塞进提示词"** —— 给 LLM / 脚本的是**语义化导航事实**，不是原始网格：

| 给谁 | 静态地形 | 动态实体 |
|---|---|---|
| 玩家（屏幕） | 全图渲染，可自由缩放拖动 | 视野内实时；视野外仅"最后目击位置 + 已过回合数" |
| LLM / 提示词托管 | 不进提示词。改为预烘焙的**区块路网**：8×8 个 16×16 区块的邻接关系 + 区块中心间 BFS 距离（一次性注入，约 256 节点摘要） | 每回合注入视野内 **15×15** 地形 ASCII（token 预算）+ **R=9** 实体清单 |
| 自制脚本 | 只读静态地形数组 + 引擎提供的 `bfsDistance(target)` / `nextStep(target)` | 同 LLM，**由引擎单点构造，脚本无法绕过** |

## 二、玩法循环

**30 秒可闭环的内核**：看见宝石 → 算这趟绕路值不值 → 走过去 → 拿到分 → 重新看出口还够不够体力。

```
[回合开始]
   └─ 引擎构造观察（我的坐标/体力/分数 + 视野内实体 + 记忆 + 公开分数榜）
        └─ 我决策：这一格往哪走？（手工 / 脚本 / LLM）
             └─ 四角色同时提交方向 → 仲裁 → 同时位移
                  └─ 扣体力 → 拾取结算 → 宝石重生判定 → 终局判定
                       └─ [回合结束] → 回到顶部
```

| 循环要素 | 设计 |
|---|---|
| 输入 | 一个方向（N/S/E/W/停留） |
| 反馈延迟 | 同回合内完成，无等待（位移 → 拾取 → 计分 一帧内连带演出） |
| 随机变量 | 宝箱奖励（1–5 分 / 25–50 体力）、宝石重生位置 |
| 决策成本 | 每步 1 点体力，不可逆 |
| 留存钩子 | 同一迷宫种子可重开（换策略 / 换托管方式），比谁分高 |

### 4.6 阻挡与死锁（e 号空洞）

| 场景 | 裁定 | 体力 |
|---|---|---|
| 目标为墙 / 越界（非法意图） | 引擎强制改为**停留**，记一次非法意图 | **扣 1** |
| 目标格被其他角色占据，且对方本回合不离开 | **停留** | **扣 0** |
| 同回合多人抢**同一空格** | **双方都不动**（v1.1 修订：撤回轮转优先级） | **双方扣 0** |
| 两角色对穿（A→B 格，B→A 格） | **双方都不动**（禁止位置互换） | **扣 0** |
| **偶数长度移动环**（最小 4 —— 3 人环与 5 人环在该网格上不存在，见 §4.6 注） | **环上全员不动** | **扣 0** |
| 链式让位（A 进 B 原格，B 本回合移走，且不构成环） | **允许，全部同时移动**（解算按固定序号 P0→P3 迭代至收敛，确定性） | 各扣 1 |
| 主动停留（Stay 意图） | 不动 | **扣 1** |
| 四面全阻（墙或角色） | 不动 | **扣 1**（v1.3 改：连通迷宫里"被墙围死"的死角不存在，四面全阻只可能是被角色堵住，属于僵持的一部分，不该免费） |
| **连续 ≥3 回合未位移**（僵持兜底 v1.3） | 不动 | **从第 4 回合起一律扣 1**，覆盖上面的"被挡扣 0" |
| 已达成出口的角色 | 立即离场，不再占格参与阻挡 | — |

**防死锁结论**：
1. **"被挡扣 0 / 主动停留扣 1"** → 堵人者每回合自付 1 点体力，卡位成为**有代价的战术**而非免费骚扰；同时被堵方不掉体力 → **堵人无法饿死对手**，杜绝 griefing。
2. **僵持兜底（v1.3 补）** —— v1.2 存在一个双方都扣 0 的永久僵持：A 在死胡同口被 B 堵（A 四面全阻扣 0），B 想进 A 的格被挡（扣 0）。加了"连续 3 回合未位移起扣 1"之后：**任何僵持都在 ≤403 回合内由体力耗尽终结**，不依赖 AI 是否聪明到会绕路。
3. **maxTurns = 600** 是第二道保险，不是唯一防线。
4. 不设"让路"规则：代价结构已让卡位自我限制，不需要额外机制。

**§4.6 注 · 环长必为偶数（QA 证明，v1.5 采纳）**

网格按 `(x+y)` 奇偶二着色，每步正交移动**必然改变着色** → 回到起点需要**偶数步** → **环长必为偶数**。

| 环长 | 是否存在 | 场景 |
|---|---|---|
| 2 | ✅ 存在 | 对穿（S3 / S4） |
| **3** | ❌ **不存在** | — |
| 4 | ✅ 存在 | 2×2 方块（S5） |
| **5** | ❌ **不存在** | — |

→ 实现里若写了"3 人环"分支，它是**死代码，应删除**（与"同格抢宝石按 actorId 升序"同属不可达分支）。

### 4.8 成长系统

## 5.0 回合内结算顺序（确定性硬约束）

同种子 + 同决策 = 完全相同对局。RNG 必须**分流**（迷宫种子 / 宝物位置种子 / 宝箱奖励种子 / 抢占仲裁种子 各自独立），方可复现与断言。

| 阶段 | 名称 | 内容 | 体力影响 |
|---|---|---|---|
| 1 | **意图提交** | 4 角色各提交一个方向。LLM 角色：本回合需重规划则先调 LLM，否则沿用当前路径下一段 | — |
| 2 | **合法性过滤** | 目标为墙 / 越界 → 强制改为「停留」，记一次非法意图 | 预扣 1 |
| 3 | **移动仲裁** | 链式让位解算（按固定序号 P0→P3 迭代至收敛）；同格抢占 → 双方不动；对穿 / 环 → 全员不动 | 失败者记 0 |
| 4 | **位移执行** | 一次性同时更新全部成功者坐标 | — |
| 5 | **体力结算** | 移动成功 -1 / 主动停留 -1 / 非法意图 -1 / 被挡停留 -0 / **四面全阻 -1** / **连续 ≥3 回合未位移 → 第 4 回合起 -1**（僵持兜底，覆盖"被挡 -0"）；**体力 ≤ 0 且不在自己出口 → 标记失败离场** | 见左 |
| 6 | **拾取结算** | 按固定序号 P0→P3：站上宝石 → +1 分且该宝石消失；站上宝箱 → 掷骰（1–5 分 / 25–50 体力）且宝箱消失。**注意：阶段 5 已判失败者不参与拾取** | 宝箱可能 +25~50（上限 400） |
| 7 | **重生与终局** | 五颗宝石全无且重生代数 < 2 → 重生一代并广播新位置；宝箱已开且间隔 ≥ 60 且重生次数 < 2 → 重生于新公平点；检查站在自己出口者 → 达成离场；回合数 +1；**回合数 = 600 → 强制终局** | — |

边界裁定：**允许"最后一步刚好上出口"** —— 体力 1 → 0 且移动后站在自己出口 → 判定达成，剩余体力记 0。

## 5.1 胜负判定（h 号空洞）

| 角色终局状态 | 判定条件 |
|---|---|
| **达成 Escaped** | 阶段 7 站在自己颜色出口格（体力 ≥ 0）→ 立即离场，记录 (分数, 剩余体力, 达成回合号) |
| **失败 Failed** | ① 阶段 5 体力归零且不在自己出口格；② 回合数达 **600** 仍未达成 |
| **结束条件（D3 裁定）** | **全部角色结算（达成 或 体力耗尽）才结束** —— 否决"玩家一结算就结束"：那会让三个 AI 被饿死、玩家也看不到对手下场，失去对比乐趣。等待感由**观战模式**解决（需求 #21） |
| **在场 Active** | 以上皆非 |

**冠军排序（逐条比较，全部可验证）**

| 序 | 规则 |
|---|---|
| 1 | 达成者 > 未达成者（未达成者不参与冠军争夺，只排名次） |
| 2 | 分数高者胜 |
| 3 | 分数相同 → 剩余体力多者胜 |
| 4 | 仍相同 → **达成回合号早者胜**（本案补充，见 §0 第 4 条） |
| 5 | 仍相同 → **平局**（并列冠军，UI 明示） |

| 边界情形 | 裁定 |
|---|---|
| 全员未达成 | **无人获胜**，显示"全员失败"；按 分数 → 剩余体力 → 移动步数少者 排名次，冠军空缺 |
| 体力归零瞬间不在出口 | **失败**（明确） |
| 体力归零瞬间在出口 | **达成**，剩余体力记 0 |
| 回合达 600 上限 | 强制终局，未达成者一律判失败 |

## 5.2 玩家托管的规则边界（信息可见性）

**铁律**：三条通道（手工 / 脚本 / 提示词托管）与三个 AI agent，**共用引擎单点构造的同一份「观察」**，任何通道无法获得超出构造器的信息。

| 通道 | 可见 | 不可见 / 受限 |
|---|---|---|
| **手工操作** | 全图地形、宝石与宝箱位置、公开 HUD、视野内对手实时位置、记忆面板 | 视野外对手实时位置（只给最后目击 + 回合戳） |
| **自制脚本**（JS 沙箱 Worker） | 只读静态地形数组、`bfsDistance(target)` / `nextStep(target)`、自身状态、已知实体清单（含记忆）、公开 HUD | ❌ 视野外对手实时坐标 ❌ RNG 种子 ❌ 未来回合信息 ❌ 网络 / 文件系统 ❌ 跨回合持久化到磁盘。单次决策超时 100ms → 强制停留 |
| **脚本异常降级链（v1.3 · 两级）** | **判定顺序固定：先判 L2，再判 L1** | **L2 严重** —— **连续 10 回合**异常（超时 / 抛错 / 返回值非法）→ **切回手动输入**（脚本彻底不可用，把控制权还给人）<br>**L1 一般** —— **累计 5 次**非法意图（非连续）→ **本局降级为每回合停留**（引擎托管，游戏继续，不打扰玩家）<br>**为什么 L2 先判**：连续 10 次必然也满足累计 5 次，不规定顺序的话 L1 会先触发把脚本架空，L2 永远达不到 |
| **提示词 AI 托管** | 与三个 AI agent **完全同构**（同一观察构造器、同一提示词模板骨架、同一实体半径 R=9、同一 15×15 patch、同一重规划频率） | 同上。玩家**只能自定义策略人格 / 系统提示词**，**不能自定义观察注入部分**（防通过提示词注入偷看全图） |
