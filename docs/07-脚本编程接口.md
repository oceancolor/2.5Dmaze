# 07 · 脚本编程接口 v2（人和 agent 共用）

> 状态：**已实现（2026-11-03）**。本文是「编写 Agent 脚本」玩法与通用 agent 接入的唯一接口文档；规则条款同步在 `SPEC.md` §6 / §9.2。
> 定位：通用 agent（WorkBuddy / Codex / Claude Code …）是**用写代码的方式玩游戏的玩家**。人和 agent 用同一套接口、同一份公开信息、同一套规则与计算预算；脚本写好一次就打完一整局，可以坐在任意座位，和手打 / 接入大模型 / 电脑同场竞技。
> 取代 05 §6 原「模式 A：卷轴 + Agent 每个决策点交一行 JSON」的设计（理由见 05 §6）。

---

## 1. 一个脚本长什么样

```js
// @maze-script name: 我的凑套脚本 | author: 张三 | origin: human     ← 文件头（导入 / 导出时用；origin: human | agent）
let exitField = null;          // 模块变量整局保留（记忆就用它）

function init(ctx, api) {      // 可选：开局调用一次（≤ 2000 ms）
  const [ex, ey] = ctx.exits[ctx.seat];
  exitField = api.field(ex, ey);
}

function decide(obs, api) {    // 必须：每回合调用一次
  return { move: 'N', intent: { type: 'gem', x: 3, y: 9, note: '补红色' } };   // 或直接返回 'N'|'E'|'S'|'W'|'STAY'
}
```

- 可以写 `export function …`（会被去掉 `export`）；**不能 import**、不能 `export default`、不能返回 Promise。严格模式、块作用域。
- `intent` 只用于显示（HUD「你的 Agent」、观战 / 结算后的名牌）和兜底（见 §5）；不合法的 intent 被忽略并提示。
- v1 写法照常可用：只有 `decide`，用 `obs.state` + `api.setState(v)`（≤ 16 KB）存记忆，`api.distance` / `api.shortestStep`。

## 2. 公开信息（所有通道同一份）

### 2.1 `ctx`（开局一次）

| 字段 | 内容 |
|---|---|
| `seat` / `size` / `mapSize` | 座位、边长、规格 `XS` … `XL` |
| `grid` | `Uint8Array`，1 = 地板，索引 `y*size+x`（拷贝，改了不影响对局） |
| `spawns` / `exits` | 四个出生点、四个出口（`exits[i]` = 座位 i 的出口，**全部公开**） |
| `rules` | `maxTurns` `stamina` `moveCost` `visionRadius` `vision{mode, delayTurns, radarEvery}` `gemColors` `gemScore` `setBonus` `gemRespawnMax` `chest{pScore, scoreRange, staminaRange, respawnTurns, respawnMax}` |

**不给**：种子、对手意图 / 计划、视野外的实时坐标、**各座位用的是什么模式**（只有手打的人能从界面名牌上看到）。

### 2.2 `obs`（每回合，与手打界面 / 大模型同源 `observe()`）

| 字段 | 内容 |
|---|---|
| `turn` `maxTurns` `gemGeneration` `gemRespawnsLeft` | |
| `self` | `seat x y stamina staminaMax score gems[5] sets exit{x,y} distToExit lowStamina inEndgame blockedStreak` |
| `actors[]` | 对手：`seat score stamina staminaMax gems sets status`（全场公开）＋ 位置（见 2.3） |
| `gems[]` | `{c, color, x, y, dist}`（位置全公开，dist = 我到它的步数） |
| `chest` | `{present, x, y, dist}` 或 `{present:false, respawnAtTurn}` |
| `events[]` | **上一回合**的公开事件（第 1 回合为空），见 2.4 |

### 2.3 对手位置

**2026-11-06 批次 6 起全公开**：所有在场对手每回合都是 `visible: true` + 实时 `x, y` + 上回合移动方向 `lastDir`；已到达 / 已出局的只有 `status`。他们要去哪（意图）不公开，要你自己推断。`ctx.rules.visionRadius`（9）不再是视野，只作「近身范围」：内置启发式只把这个范围内的对手当障碍。

推断意图的线索：移动方向与最近几回合的位置变化（他在靠近哪颗宝石 / 哪个出口）、各色持有数（他最缺哪色）、体力与到他出口的距离（快要回家了没有）、`obs.events` 里的拾取。

**SPEC-0.1 的旧规则（只在回放旧记录时出现，`ctx.rules.vision.mode`）**：`radius` 对手只在切比雪夫 9 格内实时可见、视野外给 `lastSeen {x, y, turnsSince}`，以及批次 2 实验用的：

| 规则 | 视野外的对手 |
|---|---|
| `radius`（默认） | 如上表：最后目击位置 |
| `full` | 也是 `visible: true` + 实时 `x, y` |
| `delayed` | `lastSeen` = `delayTurns` 回合前的真实位置（`turnsSince` = `delayTurns` + 1），每回合更新 |
| `radar` | 每 `radarEvery` 回合 `lastSeen` 更新为当时的真实位置；其余时间同 `radius` |

旧规则下的推断技巧（内置「预判对手（参考实现）」保留了这段逻辑，全公开时自然退化为直接用实时位置）：从最后已知位置起他走了几步 = 当时体力 − 现在体力 + 期间开箱加的体力，这是精确值；他到某颗宝石最快还要 `max(0, 距离 − 已走步数)` 步。

### 2.4 `obs.events`

| 类型 | 字段 | 谁能看到 |
|---|---|---|
| `pickup` | `seat color x y` | 全场 |
| `chest` | `seat x y kind('score'\|'stamina') value gained?` | 全场（与 HUD 播报一致） |
| `escaped` / `failed` | `seat` / `seat reason('stamina'\|'maxTurns')` | 全场 |
| `gemRespawn` / `chestRespawn` | `generation` / `x y` | 全场 |
| `bump` / `blocked` / `invalidIntent` | `seat` / `seat reason` | **只给自己** |

事件不进对局状态，不影响状态哈希与旧记录。大模型看到的局面里同样附了这些事件和对手出口。

## 3. `api`

| 方法 | 说明 |
|---|---|
| `api.field(x, y, {avoid}?)` | 以 (x,y) 为源的距离场 `Int16Array`（−1 不可达），**只读**；`avoid: [[x,y],…]` 额外当墙（不缓存）。不限次数，按计算预算计 |
| `api.dist(x, y, fromX?, fromY?)` | 最短步数，默认从自己出发（别名 `api.distance`） |
| `api.shortestStep(x, y, {avoid}?)` | 最短路下一步（同距离按 N E S W 取第一个）；已在目标 `'STAY'`；不可达 −1 |
| `api.isFloor(x, y)` / `api.size` / `api.ctx` | |
| `api.sim.step(belief, moves)` | 单回合规则推演，见 §4 |
| `api.random()` / `api.randInt(lo, hi)` | 按种子 + 座位确定的随机数；`Math.random` 也换成了同一个流 |
| `api.log(...)` | 每回合最多 20 条，显示在 HUD 控制台 / 试运行 |
| `api.budget` / `api.elapsed()` | `{turnMs, bankMs, availableMs, bankCapMs}` / 本次调用已用毫秒（用了它，评测报告会标出「结果与机器有关」） |

## 4. `api.sim.step(belief, moves)` —— 单回合规则推演

用对局**真正的结算函数** `step()` 推演一回合：同格冲突全员不动、对穿 / 环不动、链式跟进可以、撞墙不扣体力、体力归零出局、最后一步踩上自己出口算到达、座位序拾取、回合上限。规则本来公开，sim 不多给任何信息。

- `belief`（全部可选，缺省取你的观察）：`{turn, actors: {seat: {x, y, stamina, gems, status}} | [{seat, …}], gems: [{c|color, x, y}], chest: {present, x, y}, gemRespawnsLeft}`。
  **默认只有视野内的对手参与推演**；视野外的要你自己给假设位置（比如用 `lastSeen` 或推断）。
- `moves`：`['N','E',…]` 或 `{seat: move}`，缺省 `STAY`。
- 返回：`{turn, ended, actors: [{seat, known, x, y, status, stamina, gems, chestScore, score, moved, blockedStreak}], gems, chest, gemGeneration, gemRespawnsLeft, events, respawn?}`——与 belief 同形，可以自己串成多步推演。
- **不预知**：开箱事件只给 `branches: [{kind:'score', p, range}, {kind:'stamina', p, range}]`，推演结果按开箱前的分数 / 体力；宝石 / 宝箱刷新只给 `respawn: {gems|chest: true}`，不给位置。不暴露对局真实随机流。
- 非法输入（位置重叠、在墙里、移动不合法、seat 越界）抛出带说明的错误；耗时计入预算。

第一版只做单回合（多回合 rollout、信念辅助先不做，看平衡再定）。

## 5. 计算预算（方案 C）

| 项 | 值 | 说明 |
|---|---|---|
| `init` | 2000 ms | 超时：重建运行环境、跳过 init 开局（记一次提示） |
| 每回合 | 50 ms + 时间银行 | 没用完的存进银行，上限 5000 ms；超支则当回合作废、银行清零 |
| 卡死 | 可用 + 400 ms | 仍未返回 → 重建运行环境并重新 init（模块变量丢失），记一次重建；3 次 → 本局自动回家 |

- **兜底**：当回合作废（超时 / 抛错 / 返回值无效）时，引擎沿你最后声明的有效 `intent` 走（寻路 + 让行）；没有 intent 或目标已没了 → 回自己的出口。
- **降级**：累计 5 次软异常（返回值无效、v1 state 超限）→ 自动回家；连续 10 次硬异常 → 玩家座位切回手动、其他座位自动回家。
- **评测 `measure`**（命令行 / 整局试跑默认）：不打断、不作废，只统计「按正式预算会超时」的回合，所以同一脚本 + 种子的对局逐字节可复现（测试断言）。实时对局按正式预算执行。
- 预算常量在 `src/player/runtime/budget.js`，**不在 cfg 里**：配置哈希不变，旧记录照常校验；记录里只有意图，与预算无关。

## 6. 运行环境（三处同一份实现）

| 环境 | 用途 | 实现 |
|---|---|---|
| 浏览器模块 Worker | 实时对局（任意座位） | `src/player/script-host.js` + `sandbox-worker.js` |
| Node `vm` | 命令行评测 / 测试 | `src/player/node-adapter.mjs` |
| 浏览器评测 Worker | 设置页「整局试跑」 | `src/player/eval/eval-worker.js`（同步执行，不经 postMessage） |

api / ctx / 结果规范化在 `runtime/core.js`，预算 / 兜底 / 降级在 `runtime/control.js`，推演在 `runtime/sim.js`——三处共用，所以本机评测 = 游戏里的结果。这是「防误伤」边界，不是安全沙箱。

## 7. 混合对局与记录

- 座位 0：手打 / 脚本（编辑器）/ 接入大模型；座位 1–3：模拟大模型 / 本地代理 / 启发式 / **脚本**（从脚本库选）。
- 记录标签：座位 0 脚本 = `script`，其余 = `script:<代码哈希 8 位>`；`meta.scripts = [{seat, name, author, origin, codeHash}]`（代码原文不进记录）。服务器严格回放校验，`seat_stats` 归为 `script`。
- 对局中不显示对手脚本的意图；观战 / 结算后显示（与大模型对手一致）。结算卡列出各脚本座位的名称、作者、来源、耗时分位数、超时 / 异常 / 重建次数。

## 8. 脚本库

- 本机 `localStorage`（`maze.scripts.v1`，≤ 50 个、每个 ≤ 200 KB），条目 `{id, name, author, origin, code, updatedAt}`。
- 内置：`src/player/builtin/heuristic.js`（启发式参考实现：只用 v2 接口重写的内置 AI，评测基线）、`aware.js`（预判对手：用体力差推算对手走了几步，判断抢不抢得过，2026-11-06 视野实验用）、`sets.js`（凑套 + 用 `sim.step` 判断会不会被挡的示例）。
- 导入 / 导出 `.js`：文件头 `// @maze-script name: … | author: … | origin: human|agent`。

## 9. 评测：`maze-eval` 与「整局试跑」

```
npm run eval -- --script my-bot.js --size S --seeds 1-50 [--seat1 mock:bold] [--seat2 script:other.js] [--format json] [--budget enforce] [--records out/]
```

- 输出：各座位到达率 / 平均分（未到达计 0）/ 到达者均分 / 平均名次 / 冠军率；主角座位与「换成启发式」的差；每回合耗时 P50 / P95 / 最大、init 最长、按正式预算会超时的回合；前几条异常（种子 + 回合）；最差 N 局（可用 `--seeds <种子>` 单独复现）。
- 退出码：0 正常，1 参数错误，2 脚本编译失败，3 评测出错。
- 设置页「整局试跑」用同一个评测引擎（`src/player/eval/run-eval.js`），对手按当前「对手」设置（本地代理按启发式算），结果与命令行一致。

实测（每档 60 局，对手 3 个启发式）：参考脚本与原生启发式的到达率差 ≤ 1.7 个百分点、均分差 ≤ 0.08，每回合耗时 P95 < 0.5 ms。

## 10. 交给 agent：任务书

设置页「编写 Agent 脚本 → 交给我的 agent 写：任务书」生成一份 Markdown（`src/player/brief.js`）：目标、玩家要求、本规格规则参数、接口摘要、预算、评测命令（含当前规格与对手参数）、交付格式。agent 写脚本 → `npm run eval` 反复评测 → 交回带文件头的 `.js` → 玩家在设置页「导入 .js」，放在自己座位或对手座位。
